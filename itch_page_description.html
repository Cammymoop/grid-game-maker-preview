Grid Game Maker is a free tool for easily turning your grid-based ideas into games quickly and with pretty visuals.

You can play any of the three full example games or edit them, create levels, make games from scratch, or import games created by other people to play or to play around with.

This is the first public release! Thanks for checking it out. "Preview" means things are subject to change in later versions, but this is the full version not a demo.

Why "Preview" though?

This is the Preview version which is basically the 1.0 version based off the code I've been working on for several years. I decided to call this first version "Preview" because it is a quick-and-dirty expansion of my working prototype so I can get it out there and see what I and others can make with it. It includes many compromises and incomplete features, some of which may be very different or even removed in later versions.

This version is free and open source, as I intend all future versions to be, and will be somewhat supported for quite a while. But another reason for the "Preview" naming is that from now on my focus with GGM will be primarily on a full rewrite for the next version and beyond. The current state of the code and baggage of multiple years and many different ideas wont make for a good foundation of what I want GGM to be. This does mean the next version will not be coming very soon but I hope the wait will be exciting at least!


Playing games, importing games, custom levels & level packs

First choose the currently loaded game to play on the main menu by highlighting the game title option and pressing left/right or clicking the arrows to cycle through games. Click the list menu icon or press Menu Confirm while the title option is selected to open the list of all installed games to choose from.

To install and play a .zip game use the "Create or Import" button from the main menu and select or upload the game's zip file, no need to unzip it.

Before importing custom levels or levelpacks, make sure that the game they were created for is loaded by selecting it on the main menu. Levels and level packs for existing games are imported from a .json file; Use the "Import Levels" button on the main menu or in the level select menu while playing that game.

About "released versions" and Game IDs

Games may be a "release version" which is a specific, unmodified version of a game. On the main menu, release versions show a white title with no orange border. Custom levels can be created for release versions, but to modify the game, graphics, or builtin levels or lists you need to unlock the game by creating an "edited version" which is a copy of the release version. Clicking "Edit Game" from the main menu will open a dialog that gives you a couple options on how to do this. When modifying an existing game it is recommended to set a default identifier in your profile settings which is used like a prefix for the game ID so that original and modified versions are identifiable and show up as separate choices in the main menu.

Only one version of a particular game id (including prefix) is loaded at a time. Different installed versions can be switched between on the main menu if the version switcher is enabled in your profile options. Every installed release version of a game is kept by default, and GGM may create and keep backup copies of edited versions such as when importing over the current edited version.


Important Note For Editing With the Web Version

If editing games or levels in the web version, please make sure to export the game or custom levels frequently and backup those copies appropriately. Browser storage (IndexedDB) is used to save games, levels, profiles, and save files. In practice this save data may be kept by your browser for an indefinite amount of time, but it should not be considered a reliable place to permanently keep your games. It is entirely up to the browser how and when to keep or get rid of this data, and it is also easily possible to accidentally clear this data.

AI Usage

Some limited code generation (Models from OpenAI, Anthropic, Cursor, used through Cursor IDE).
GGM is not vibe-coded, not vibe-designed, and is not a tool which integrates content-generating AI in any way.

Exposition about AI usage and GGM's (my) stance on it.

GGM is a project I have been working on since well before AIs capable of helping write code or helping in any material way existed. More recently with some of these tools available I have expiremented in using them as tab-completion or to code a first version of some easily specified and self-contained sub-system I had in mind. I generally approach the question of whether or not to use AI for code as a practical question. The state of the GGM code by the time this became an option, was simply not a good match for any more extensive usage.

Going forward, I plan to continue with some amount of AI code alongside my own code. I currently see no reason however, to use AI for graphics or music in particular, and beyond that, it will probably not be used as a part of any content or system that players or game creators directly interact with.

Grid Game Maker is a tool that I created as a human who wanted it to exist, for humans to enjoy and perhaps even get some tangible practical value from as well. I think that making games should continue to be fun and personal; I want people to be able to have a deep connection with games, mods or anything else they use GGM to make. GGM should provide a delightful and easy way to do all the individual things that go into making a game, it is a set of paints, brushes, stickers, crayons, stencils, scissors, glue, and sparkles for you to apply to a blank canvas. It is not, and has no intention to be, an artist in and of itself.
